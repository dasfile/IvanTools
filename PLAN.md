# Техническое задание и план: AdjustToFace (IvanTools)

Инструмент для Autodesk Revit 2023 на C#, предназначенный для выравнивания вершин измененной формы перекрытия или кровли (`SlabShapeEditor`) по плоскости выбранной плоской грани существующего объекта.

## 1. Назначение и логика работы

1. **Выбор хост-элемента:** пользователь выбирает перекрытие (`Floor`) или кровлю (`RoofBase`). Кликнуть что-то другое нельзя — стоит фильтр выбора `SlabHostSelectionFilter`.
2. **Проверка режима формы:** если у элемента выключено редактирование формы (`editor.IsEnabled == false`), выводится диалог с предупреждением о том, что отключить режим обратно средствами API нельзя (только `ResetSlabShape`), и предлагается его включить (`editor.Enable()`).
3. **Выбор целевой грани:** пользователь указывает грань любого другого объекта. Грань самого хост-элемента выбрать нельзя (`TargetFaceSelectionFilter`). Если грань не плоская или её нормаль вертикальна — выводится сообщение, и выбор повторяется (выход — Esc).
4. **Проверка плоскости:** извлекаются `Origin` и `FaceNormal`. Если `Math.Abs(normal.Z) < 1e-6` — грань вертикальна, выравнивание по вертикально перемещаемым вершинам невозможно (сообщение + повтор выбора).
5. **Выбор базы выравнивания:** определяется толщина конструкции элемента; если она известна, задается вопрос «Выравнивать по нижней грани?» (Да — вершины поднимаются на толщину, на плоскость ложится низ элемента; Нет — верх). Подробно см. раздел 2.
6. **Пересчет координат:** для каждой вершины из `editor.SlabShapeVertices` вычисляется целевая отметка по формуле плоскости с учетом вертикального смещения:
   `zTarget = origin.Z - (normal.X * (pos.X - origin.X) + normal.Y * (pos.Y - origin.Y)) / normal.Z + verticalOffset`
7. **Применение:** отметка задается через `editor.ModifySubElement(vertex, offset)` внутри одной транзакции, затем `doc.Regenerate()`, `tx.Commit()` и `uidoc.RefreshActiveView()`.
8. **Ошибка на отдельной вершине** (дуговая кромка, конфликт с соединениями и т.п.) не отменяет всю операцию: собирается сводка «выровнено N, не удалось M» (первые 10 ошибок) и строка про применённое смещение. Если не удалось ни одной — транзакция откатывается.

## 2. Выравнивание по верхней или нижней грани

`SlabShapeEditor` правит **верхнюю** поверхность плиты/кровли, а нижняя идет за ней на толщину конструкции. Поэтому при выравнивании по грани верх ложится на плоскость, а низ оказывается на толщину ниже — элемент визуально «утопает».

Решение: диалог `Да/Нет` после выбора грани (шаг 5 логики):

* **Да** — `verticalOffset = +толщина`: на плоскость ложится низ элемента;
* **Нет** — `verticalOffset = 0`: на плоскость ложится верх (поведение по умолчанию).

Толщина (`GetHostThickness`, в футах) берется по цепочке:

1. инстанс-параметр `ROOF_ATTR_THICKNESS_PARAM` (кровля) / `FLOOR_ATTR_THICKNESS_PARAM` (перекрытие);
2. `doc.GetElement(host.GetTypeId()) as HostObjAttributes` → `GetCompoundStructure().GetWidth()`;
3. если ничего не найдено — `0`: диалог не показывается, работаем по верхней грани, в сводке пишется «толщина конструкции не определена».

Перевод единиц: `UnitUtils.ConvertFromInternalUnits(thickness, UnitTypeId.Millimeters)`.

**Ограничение:** смещение вертикальное (`+толщина`). Толщина конструкции в Revit измеряется по нормали к поверхности, поэтому для наклонной целевой грани строгий вариант был бы `+ толщина / |normal.Z|`. Для горизонтальной грани разницы нет; ошибка растёт как `t · (1/|n.Z| − 1)` (при `t` = 10 мм: уклон 15° ≈ 0.35 мм, 30° ≈ 1.5 мм, 45° ≈ 4.1 мм).

## 3. Адаптивный алгоритм `ModifySubElement` (важно)

В Revit 2023 у `SlabShapeEditor` есть только две перегрузки:

```csharp
void ModifySubElement(SlabShapeVertex vertex, double offset);
void ModifySubElement(SlabShapeCrease crease, double offset);
```

Что именно означает `offset` — **в API не документировано** (справка Autodesk по этому члену пустая, SDK/CHM нет). Возможны два прочтения:

* абсолютная отметка Z (`base = 0`);
* смещение от исходной (неизмененной) плоскости элемента, то есть от исходной отметки самой вершины.

У `SlabShapeVertex` нет свойства «offset», только `Position` и `VertexType`, поэтому узнать семантику из данных нельзя. Поэтому в `SetVertexElevation` используется **самокалибрующийся** подход: результат считается аффинным с наклоном 1 (`z = base + offset`), значение `base` замеряется по факту, после чего аргумент пересчитывается:

```
argument = zTarget;                                    // первое приближение
loop (до 3 попыток):
    ModifySubElement(vertex, argument); Regenerate();
    z = текущая Position.Z вершины;
    если |z - zTarget| <= 1e-4 ft  -> готово;
    base     = z - argument;                           // замер
    argument = zTarget - base;                         // пересчет
```

* абсолютная семантика — сходится с первого вызова;
* относительная — со второго;
* если вершина уже стоит на месте, правка фактически не меняется.

**Обязательное следствие:** после `ModifySubElement` + `Regenerate()` объекты `SlabShapeVertex` устаревают, поэтому вершина переискивается в свежей коллекции `editor.SlabShapeVertices` **по координатам X/Y** (при вертикальном перемещении они не меняются). Порядок вершин в коллекции API не гарантирует, поэтому сопоставление по индексу не используется. Если X/Y совпали у нескольких вершин — берется ближайшая по Z к исходному положению.

## 4. Требования к среде и компиляции

* **Платформа:** Autodesk Revit 2023 (.NET Framework 4.8).
* **Компилятор:** `csc.exe` из комплекта .NET Framework (`v4.0.30319`), стандарт **C# 5**.
* **Ограничения синтаксиса C# 5:**
  * без интерполяции строк (`$"..."`) — использовать `string.Format()` или конкатенацию `+`;
  * без объявления `out`-переменных внутри вызова метода (`out int x`) — объявлять заранее;
  * без кортежей (Tuples) — вместо них отдельные классы (например, `VertexTarget`).
* **Кодировка исходника:** UTF-8 **с BOM** (иначе `csc`/HotLoader на машине с ANSI 1251 могут испортить кириллицу в строках).
* **Примечание по Revit 2023 API:** доступ к `SlabShapeEditor` у `Floor` и `RoofBase` — только через **свойство** `.SlabShapeEditor`. Методов `GetSlabShapeEditor()` в этой версии API нет (проверено рефлексией по `RevitAPI.dll`).
* `ISelectionFilter` в Revit 2023: `PickObject(ObjectType, ISelectionFilter, string)` — доступна, используется для обоих выборов.
* Исключение отмены (Esc) — `Autodesk.Revit.Exceptions.OperationCanceledException`, а не `System.OperationCanceledException` (в файле подключено через alias `RevitCanceledException`).

```text

├── IvanTools.addin
└── IvanTools\
    ├── AdjustToFace.cs          <- запуск через CsHotLoader (Run Script)
```

Для запуска через `CsHotLoader` достаточно положить `AdjustToFace.cs` в папку `IvanTools\` и нажать **HotLoader → Run Script**. Перезапуск Revit не нужен: правим `.cs` — снова Run Script.

Для кнопки в манифесте — собрать `AdjustToFace.dll` и добавить в `IvanTools.addin`:

```xml

    <AddInId>7E3C1A90-2B44-4F17-9C6B-5D0A11B2C3D4</AddInId>
```

`AddInId` должен быть уникальным для всех плагинов — при добавлении в манифест проверить, что такого GUID ещё нет.

## 8. Известные ограничения

* `Enable()` включает режим формы необратимо: отключить его через API нельзя, только `ResetSlabShape()` (сброс всех правок формы). Поэтому включение подтверждается пользователем в диалоге.
* Вершины на дуговых кромках или в местах сложных соединений могут не поддаваться правке — такие случаи попадают в сводку ошибок, остальные вершины выравниваются.
* Грань с вертикальной нормалью не подходит: вершины перемещаются только по Z, такой грани не существует как функции `z(x, y)`.
* Связи (linked models) не поддерживаются: `PickObject` без `ObjectType.LinkedElement` работает только в активном документе.
* Повторный запуск на уже выровненных вершинах безопасен: расхождение 0, `ModifySubElement` вызывается с тем же результатом.
* Для проверки на реальной модели стоит один раз посмотреть, сколько вызовов делает `SetVertexElevation` (1 — абсолютная семантика offset, 2 — относительная). На результат это не влияет, только на скорость работы с большим числом вершин.
* Толщина для режима «по нижней грани» берется из инстанс-параметра, а при его отсутствии — из `CompoundStructure` типа. У элемента с толщиной, переопределённой нестандартно (переменный слой, несколько регионов), фактическое значение показывается в диалоге: если оно не совпадает с ожидаемым, выбираем «Нет» и правим отметку вручную.
* Режим «по нижней грани» смещает вершины вертикально на толщину. Для наклонных целевых граней см. ограничение в разделе 2.

| `IvanTools.SlabHostSelectionFilter` | разрешает кликать только `Floor`/`RoofBase` |
| `IvanTools.TargetFaceSelectionFilter` | запрещает выбирать грань самого хост-элемента |
